## 一、策略概述

**五福闹新春** 是一个基于 **动量得分** 的 ETF 轮动策略，核心逻辑是：

1. 从全市场 ETF 池中筛选流动性达标的 ETF
2. 计算加权线性回归动量得分（年化收益率 × R²）
3. 根据大 A 走弱/正常两种市场状态，应用不同的过滤条件
4. 持有动量得分最高的 1 只 ETF，每日 13:10 调仓
5. 分钟级固定止损（成本价 × 95%）作为风控兜底

---

## 二、策略架构

### 2.1 每日执行流水线

```
09:00  晨间流水线
  ├── 持仓检查
  ├── 回撤监控（阈值 3%）
  └── 全市场ETF流动性阈值计算

09:40  走弱期判断 + 池子更新
  ├── 大A走弱期判定（4指数 vs MA10）
  └── ETF池更新（走弱期→全球池 / 正常期→动态池+固定池）

13:10  午盘流水线（核心交易时段）
  ├── 动量计算与排序
  ├── 卖出操作（不在目标池的持仓）
  └── 买入操作（目标池中的新ETF）

15:10  收盘流水线
  └── 重置价格缓存

每分钟  分钟级固定止损
  └── 检查持仓是否跌破成本价×95%
```

### 2.2 ETF池体系

策略维护了 **三层 ETF 池**，根据市场状态动态切换：

| 池子 | 内容 | 数量 | 使用场景 |
|------|------|------|----------|
| 全球/海外ETF池 | 大宗商品(5) + 海外市场(12) | 17只 | 走弱期专用 |
| 中国ETF池 | 港股(13) + 指数(12) + 行业(67) | 92只 | 正常期固定池 |
| 动态ETF池 | 全市场ETF按行业分组取流动性最佳 | ≤300只 | 正常期补充池 |

**正常期**：合并池 = 固定池（流动性过滤后） + 动态池
**走弱期**：合并池 = 全球/海外ETF池（流动性过滤后）

## 三、核心算法详解

### 3.1 动量得分计算（加权线性回归法）

这是策略的灵魂，采用 **加权最小二乘法（WLS）** 对对数价格序列做线性回归：

```
1. 取 lookback_days(25) + 1 个收盘价
2. y = ln(price_series)           # 对数价格
3. x = [0, 1, 2, ..., n]         # 时间序列
4. weights = linspace(1, 2, n)²   # 二次递增加权（近期权重更大）
5. WLS回归 → slope, intercept
6. annualized_returns = exp(slope × 250) - 1   # 年化收益率
7. R² = 1 - SS_res / SS_tot                    # 拟合优度
8. momentum_score = annualized_returns × R²     # 动量得分
```

**设计意图**：
- **对数价格**：将指数增长转化为线性，使回归更合理
- **二次递增加权**：近期数据权重更大（1→4），捕捉趋势变化
- **R² 乘法**：惩罚趋势不稳定的 ETF，R² 低说明走势杂乱
- **年化收益率**：将日频斜率转换为可理解的年化指标

### 3.2 大A走弱期判定

使用 4 个 A 股核心指数与 MA10 的关系判断市场状态：

| 指数 | 代码 | 代表 |
|------|------|------|
| 大盘 | 000300.XSHG | 沪深300 |
| 小盘 | 399101.XSHE | 中证等权重 |
| 创业板 | 399006.XSHE | 创业板指 |
| 中证A500 | 000510.XSHG | 中证A500 |

**判定规则**：
- **进入走弱期**：≥3/4 指数低于 MA10
- **退出走弱期**：≥3/4 指数站上 MA10
- **强制退出**：走弱期持续 ≥20 个交易日

**走弱期的意义**：A 股走弱时，策略切换到全球/海外 ETF 池，避免在下跌市场中持有 A 股 ETF，转而配置黄金、原油、纳指等负相关或独立走势的资产。

### 3.3 过滤条件体系

策略在不同市场状态下应用不同的过滤条件：

| 过滤器 | 条件 | 正常期 | 走弱期 | 说明 |
|--------|------|--------|--------|------|
| 动量得分 | 0 ≤ score ≤ 5 | ✅ | ✅ | 排除极端值 |
| R² 过滤 | R² > 0.4 | ✅ | ❌ | 正常期要求趋势稳定 |
| 均线过滤 | 价格 > MA10 × 1.0 | ❌ | ✅ | 走弱期要求站上均线 |
| 成交量过滤 | 量比 < 1.8 | ✅ | ✅ | 排除异常放量（可能见顶） |
| 短期风控 | 近3日单日跌幅 < 3% | ✅ | ✅ | 排除急跌标的 |

**设计逻辑**：
- 正常期用 R² 过滤（要求趋势稳定），走弱期用均线过滤（要求价格站上均线）
- 成交量过滤是反向的：量比过高（>1.8）反而被排除，逻辑是异常放量可能是见顶信号
- 短期风控排除近3日有单日跌幅超3%的标的

### 3.4 候选池确定与持仓调整

```
1. 过滤后按动量得分排序，取前10名
2. 以第 holdings_num(1) 名的得分 × 0.9 作为阈值
3. 得分 ≥ 阈值的ETF进入候选池
4. 优先保留当前持仓中在候选池的ETF
5. 不足部分从候选池按得分补充
```

**持仓惯性设计**：当前持仓如果在候选池中，优先保留，避免频繁换仓。只有当持仓 ETF 动量得分跌出候选池时才卖出。

## 四、风控体系

### 4.1 分钟级固定止损

- **触发条件**：当前价 ≤ 成本价 × 95%（即亏损 ≥5%）
- **执行时间**：09:40-10:29、10:40-11:30、13:00-14:57（避开开盘和尾盘）
- **执行方式**：通过 `smart_order_target_value` 卖出全部持仓

### 4.2 回撤监控

- **阈值**：3%
- **记录**：超过阈值时记录日期、回撤幅度、持仓信息、市场状态
- **注意**：仅记录预警，不触发自动操作

### 4.3 智能下单保护

`smart_order_target_value` 函数包含多层保护：

| 保护层 | 逻辑 |
|--------|------|
| 全天停牌 | 跳过交易 |
| 盘中临时停牌 | 检查近10分钟成交量，全为0则跳过 |
| 涨停/跌停 | 均不交易（统一处理） |
| 最小交易额 | 交易金额 < 10元跳过 |
| T+1检查 | 当天买入不可卖出 |
| 现金不足 | 二次校验可用现金，避免超买 |
| 佣金+滑点预估 | 买入时用含成本价计算股数 |

## 六、策略优势

### 6.1 多市场配置能力
走弱期自动切换到全球/海外 ETF 池，具备跨市场配置能力，不局限于 A 股。

### 6.2 动量+趋势质量双重筛选
动量得分 = 年化收益率 × R²，既要求有趋势（收益率），又要求趋势稳定（R²），避免选中走势杂乱的高波动标的。

### 6.3 持仓惯性减少换仓
优先保留当前持仓中的候选 ETF，减少不必要的换仓，降低交易成本。

### 6.4 多层风控
分钟级止损 + 回撤监控 + 短期风控过滤 + 涨跌停保护 + T+1检查，风控体系较为完善。

### 6.5 动态ETF池
正常期通过全市场扫描 + 行业分组 + 流动性筛选构建动态池，能捕捉新上市的高流动性行业 ETF。

## 七、策略风险与不足

### 7.1 集中持仓风险
仅持有 1 只 ETF，单日最大回撤可能很大。虽然设有 5% 止损，但跌停时无法卖出，实际亏损可能远超 5%。

### 7.2 日频调仓的时序风险
所有交易在 13:10 执行，这是策略文章标题提到的"13:10 狙击"问题。如果大量资金跟随此策略在同一时间交易，可能造成：
- 滑点增大
- 涨跌停无法成交
- 策略容量受限

### 7.3 走弱期判定的滞后性
MA10 是滞后指标，当 3/4 指数跌破 MA10 时，市场往往已经下跌了一段。走弱期进入信号滞后，退出信号也滞后。

### 7.4 R² 过滤的局限性
R² 衡量的是对数价格线性拟合的优度，但：
- 震荡上涨的 ETF（R² 低但持续上涨）会被错误排除
- 短期暴涨的 ETF（R² 高但可能见顶）会被错误纳入

### 7.5 成交量过滤的反直觉
量比 > 1.8 被排除，逻辑是"异常放量可能见顶"。但放量突破也是常见形态，此过滤可能错过趋势启动点。

### 7.6 动态池的行业分组粗糙
用 ETF 名称前2个字作为行业分组键，容易产生错误归类。例如"半导体设备"和"半导材料"会被分到不同组（"半导" vs "半导"），但"银行ETF"和"银行红利"会被分到同组。

### 7.7 防御ETF选择
511880.XSHG 是银华日利（货币基金），作为防御资产收益极低。走弱期如果全球 ETF 也无合格标的，策略会持有货币基金，实质上等于空仓。

### 7.8 回测设置偏乐观
- 滑点仅 0.01%，对于日频调仓策略偏小
- 佣金万分之一 + 最低5元，小额交易时佣金占比高
- 未考虑冲击成本（大资金买入时价格会被推高）

## 八、关键代码逻辑审查

### 8.1 动量得分计算中的潜在问题

```python
# 第713行：权重计算
weights = np.linspace(1, 2, len(y))
W = weights ** 2  # 实际权重范围 [1, 4]
```

权重是先线性递增再平方，实际权重从1到4，近期数据权重是远端的4倍。这个设计是合理的，但文档注释说"二次递增加权"容易误解为权重直接是二次函数。

### 8.2 成交量预估的时区处理

```python
# 第798-802行
elapsed_minutes = (now.hour - 9) * 60 + now.minute - 30
if now.hour >= 13:
    elapsed_minutes -= 90  # 减去午休时间
```

这里假设交易时间为 9:30-11:30 和 13:00-15:00，共240分钟。计算逻辑正确，但边界情况（如 13:00 整）需要验证。

### 8.3 卖出和买入在同一时间执行

```python
# 第203-205行
run_daily(sell_routine, time='13:10')
run_daily(buy_routine, time='13:10')
```

三个函数都在 13:10 执行，聚宽的执行顺序是注册顺序。`afternoon_routine` → `sell_routine` → `buy_routine`，这个顺序是正确的（先计算→再卖出→再买入），但依赖注册顺序是隐式逻辑，不够健壮。

### 8.4 走弱期延续时重置计数器

```python
# 第860-862行
elif weak_condition_met:
    old_start = g.weak_start_date
    g.weak_start_date = today
    g.weak_days_count = 0
```

走弱期内如果再次满足进入条件，会重置 `weak_start_date` 和 `weak_days_count`，这可能导致走弱期永远无法触发"最长持续天数"的强制退出。这是一个 **逻辑漏洞**：走弱期内持续满足走弱条件时，计数器不断重置，20天强制退出永远不会触发。

## 九、改进建议

### 9.1 修复走弱期计数器重置问题
走弱期内再次满足条件时，不应重置 `weak_start_date`，应保持原始进入日期：

```python
elif weak_condition_met:
    # 不重置 weak_start_date，保持原始进入日期
    log.info(f"🟡 【走弱期延续】再次触发进入条件，保持原始计数")
```

### 9.2 增加持仓数量
从 1 只增加到 2-3 只，降低集中持仓风险。同时调整资金分配逻辑。

### 9.3 分散交易时间
将交易时间从固定 13:10 改为 13:10-14:00 之间随机偏移，减少时序冲击：

```python
import random
trade_minute = random.randint(10, 59)
run_daily(sell_routine, time=f'13:{trade_minute:02d}')
```

### 9.4 增加趋势确认指标
在动量得分之外，增加 MACD 或 ADX 等趋势确认指标，避免在趋势末期入场。

### 9.5 优化行业分组逻辑
用 ETF 跟踪指数的行业分类代替名称前2字分组，可使用聚宽的 `get_industry` API。

### 9.6 增加最大回撤止损
当策略回撤超过阈值（如 10%）时，清仓转入防御 ETF，而非仅记录预警。

### 9.7 提高滑点假设
日频调仓策略建议滑点设为 0.05%-0.1%，更贴近实际。
